# Event Bus

Event Bus разделяет производителей и потребителей событий Alpha Core. Производитель публикует immutable event и не знает, какие handlers его обрабатывают.

## Контракты

- `BaseEventBus` определяет `subscribe(event_type, handler)` и async `publish(event)`;
- `EventHandler` — асинхронная функция, принимающая одно событие;
- `InMemoryEventBus` — локальная MVP-реализация без внешнего брокера.

## Поведение InMemoryEventBus

- подписка выполняется по точному классу события;
- на один тип можно подписать несколько handlers;
- `publish()` ждёт завершения всех handlers;
- handlers одного события запускаются конкурентно;
- исключение одного handler логируется и не отменяет остальные;
- событие без подписчиков завершается без ошибки;
- каждый владелец процесса создаёт собственный экземпляр Event Bus.

## Границы

Event Bus не знает о Collector, Knowledge или других доменных модулях. Конкретные события определяются владельцами событий. `CollectionCompleted` расположен в `core/collector/events.py`.

In-memory реализация не гарантирует durable delivery, межпроцессный обмен, повторную доставку или сохранение порядка между параллельными публикациями.
